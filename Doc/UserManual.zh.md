## 1. 运行环境

- 操作系统：Windows 10 / Windows 11，64 位。
- 运行库：随安装包部署的 Qt 6.11.1 运行库与 Python 3.14 运行环境。
- 显示分辨率：推荐 1920×1080；1024×768 等紧凑尺寸会自动收起部分面板。
- 扫码设备：支持键盘模拟输入的扫码枪，条码输入框获得焦点时可直接扫码。
- 网络：连接 MES 时需可访问服务器地址；无网络时自动切换本地工作模式。

## 2. 安装与启动

### 安装

1. 以管理员身份运行安装包 `Setup_TreeATE_x64_V3.1.0.exe`。
2. 按向导选择安装目录，默认目录为 `{pf}\TreeATE`。
3. 安装程序会一并部署 `Example` 示例工程与 `Config\sys.cfg` 初始配置，并在安装目录下附带 `THIRD-PARTY-NOTICES.txt`、`Changelog.txt` 与 `COPYRIGHT`。
4. 安装完成后，可从开始菜单或桌面快捷方式启动 TreeATE。

### 启动

双击 `TreeATE.exe` 启动主程序。首次启动会弹出登录对话框；登录成功后才可加载测试工程并执行测试。

> 绿色版运行方式：在构建输出目录（例如 `build\...\bin\x64`）确认已执行 `windeployqt` 并复制 `PythonQt-Qt6-Python3.14.dll`，直接运行 `TreeATE.exe` 即可。

## 3. 登录系统

进入 TreeATE 需要权限。打开程序后会出现登录对话框，输入正确的用户名和密码即可。

- 默认本地调试账号：`admin`，密码：`123`。
- 本地模式仅用于现场调试；正式产线建议连接 MES 服务器，以便工序管控。
- 服务器地址可在登录界面选择，也可在进入系统后通过“系统 → 系统选项”配置。

> **警告**：本地模式不会把测试结果提交 MES，可能造成工序不受控。生产环境请使用服务器模式并确认产线、工站配置正确。

v3.1.0 主界面自上而下分为应用栏、条码工具栏、错误横幅、UUT 工作区、底部信息区与状态栏。

| 区域 | 说明 |
| --- | --- |
| 应用栏 | 品牌与版本、☰ 菜单、加载 / 测试 / 停止 / 属性、产线工站、语言、主题、退出 |
| 条码工具栏 | 条码输入框、最右侧测试状态位 |
| 错误横幅 | 警告 / 错误分级提示，可带操作按钮，限时自动隐藏 |
| UUT 工作区 | 每个测试工程一个顶部页签；通过 / 失败 / 异常 / 总数 / 通过率 KPI；右侧属性检查器默认约 320px，可收起 |
| 底部信息区 | 日志、计数等页签；日志支持暂停、清空、复制 |
| 状态栏 | 工程路径（点击复制）、历史结果、当前用户、设备 ID、当前时间 |

### UUT 工作区

- 每加载一个测试工程，工作区新增一个顶部页签。
- 每个页签内展示该工程的测试树与 KPI：通过、失败、异常、总数、通过率。
- 可通过“视图”菜单切换平铺、并排、标签全屏等显示方式。
- 未加载任何工程时，工作区中央显示“请加载测试工程后启动测试”。
- 测试结果可在测试树上以浮层形式查看，按 `Esc` 关闭。

### 属性检查器与底部信息区

- 属性检查器位于右侧，未选中测试工程时显示操作引导；选中后显示可编辑属性。
- 底部信息区包含日志与计数页签；计数展示良品次数与不良次数。
- 日志工具支持暂停、清空、复制，便于现场排查。
- 状态栏的工程路径可点击复制；历史结果显示为圆点标识，橙色表示存在未上传的本地结果。

## 5. 配置系统选项

选择菜单“系统 → 系统选项”，打开系统配置对话框。

| 配置项 | 说明 |
| --- | --- |
| 产线名称 | 用于区分不同产线，工厂内应唯一，命名规则自定义。 |
| 工站名称 | 标识工位测试名称，例如老化测试、整机测试 1、整机测试 2；同一产线内可不唯一。 |
| 服务器 | TreeATE 与 MES 对接的服务器地址，也会出现在登录界面。 |
| 界面语言 | 简体中文或 English；v3.1.0 起也可在应用栏直接切换，立即生效。 |
| 界面主题 | 经典、浅色、深色；也可在应用栏切换，选择会被记住。 |
| 工作路径 | 测试工程根目录。可点击“...”选择，也可直接输入，例如 `D:/Projects/TreeATE/Example`。建议所有工程统一存放。 |
| 扫码加载规则 | 配置产品条码规则与测试工程相对路径，实现扫码自动加载。 |

### 配置扫码加载规则

1. 在“扫码加载规则”区域点击“+”新增一条规则。
2. 在“产品条码正规匹配式”中填写条码规则，一般为产品类型前缀。例如条码 `21201345678` 中，`212` 为产品类型，可填写 `212`。
3. 在“测试工程路径和名称”中填写相对于工作路径的工程路径。例如工程为 `D:\Projects\TreeATE\Example\TestDemo\TestDemo.tpx`，工作路径为 `D:\Projects\TreeATE\Example`，则填写 `/TestDemo/TestDemo.tpx`。
4. 路径分隔符统一使用 `/`。
5. 点击“OK”保存，点击“Cancel”放弃修改。

## 6. 加载测试工程

进入系统后，需要加载由 TreeATE Copilot 配置的测试工程才能执行测试。加载方式有两种：

### 手动加载

1. 点击应用栏“加载”，或选择菜单“测试工程 → 加载”，或按 `F2`。
2. 在文件对话框中定位 `*.tpx` 文件并打开。
3. 加载完成后，工作区出现对应页签，显示测试工程、测试套、测试项的名称、描述、测试状态、测试标准、开始时间与测试用时。

### 扫码自动加载

1. 确认已在系统选项中配置条码规则与工程相对路径。
2. 点击条码输入框或按 `Ctrl+L` 定位。
3. 扫描被测产品条码并回车，系统按规则匹配并自动加载对应工程。

> 支持同时加载多个测试工程，多个工程可并行测试。一个测试工程可包含多个测试套，一个测试套可包含多个测试项。

## 7. 修改测试工程选项

选择菜单“测试工程 → 选项”，打开工程选项对话框。

| 选项 | 说明 |
| --- | --- |
| 测试工程名称 | 仅显示，由开发者定义，不可修改。 |
| 测试工程描述 | 仅显示，由开发者定义，不可修改。 |
| 被测产品条码正则匹配 | 仅显示，由开发者定义条码匹配与检查规则。 |
| 整体循环测试次数 | 设置测试工程整体循环次数，最大不超过 100 万次。 |
| 测试失败则停止 | 两个可选项：当次失败后停止后续未开始测试项；循环测试中遇到失败时停止后续循环。 |

## 8. 修改测试工程属性

1. 在工作区选中测试工程节点。
2. 选择菜单“测试工程 → 属性”，或点击应用栏“属性”，右侧显示属性检查器。
3. 属性内容随工程配置不同而不同，仅显示当前工程的可修改属性。
4. 修改属性值后，点击属性面板下方“保存”使其生效。

> 未选中工程时属性检查器显示操作引导；在 1024×768 等紧凑窗口下属性面板会自动收起，可通过应用栏“属性”按钮或“视图”菜单重新打开。

## 9. 开始测试

1. 确认已加载测试工程，并在测试树中勾选一个以上需要执行的测试项。勾选表示测试，未勾选表示跳过。
2. 在条码输入框中扫描或输入被测产品条码。若工程配置了条码规则，系统会自动校验，不符合规则时提示并禁止测试。
3. 点击应用栏“测试”、选择菜单“测试工程 → 测试”，或按 `F5` 开始测试。
4. 测试过程中，条码工具栏右侧状态位显示“测试中 / GO...”，测试树与 KPI 实时更新。
5. 测试完成后，状态位显示“完成 / Done”（通过）、“失败 / Failed”或“ERROR”（异常）。

### 扫码开始测试

当条码规则与工程已就绪时，可直接扫描产品条码开始测试，无需再用鼠标点击“测试”。

> 开始测试前必须输入条码，并至少勾选一个测试项。未加载工程时工作区会提示“请加载测试工程后启动测试”。

## 10. 停止测试

在测试过程中，点击应用栏“停止”、选择菜单“测试工程 → 停止”，或按 `F8` 发出停止请求。

> **警告**：停止测试仅在测试项之间生效。如果当前测试项耗时较长，为保护测试过程与相关系统配合的安全性，不会立即中断，而是在当前测试项完成后、下一个测试项开始前停止。

## 11. 测试状态说明

条码工具栏最右侧状态位用于快速判断当前测试阶段，文字与颜色同步变化：

| 状态 | 状态位显示 | 颜色与含义 |
| --- | --- | --- |
| Unload | 未加载 | 灰色。尚未加载测试工程或工程已关闭。 |
| Loading | 加载中 | 蓝色。正在解析并加载测试工程。 |
| Ready | 就绪 | 青绿色。工程已加载，等待输入条码并开始测试。 |
| GO | 测试中 | 琥珀色。测试正在执行。 |
| Pass | 完成 | 绿色。本轮测试完成且结果通过。 |
| Fail | 失败 | 红色。测试结果未通过。 |
| Exception | 错误 | 橙黄色。测试过程出现异常或错误，英文界面显示 ERROR。 |

> “完成”与计数卡片标题“良品次数”使用不同文案来源，避免状态位误显示计数标题。英文界面下对应显示 Unload、Loading...、Ready、GO...、Done、Failed、ERROR。

## 12. 查看本地测试结果

选择菜单“系统 → 本地测试结果”，打开 TreeResults 查询台。

### 结果层级

1. **测试工程结果**：条码、开始测试时间、产线、工位、总测试结果等。
2. **测试项结果**：测试项结果（Pass、Fail 等）、描述等。
3. **详细测试结果**：测试项中的各条详细测试记录。

三者是父子关系：测试工程结果包含多条测试项结果，测试项结果包含 0 至多条详细结果。点击父级行可展开子级。

### 查询与导出

- 结果库以只读方式打开，避免误改历史数据。
- 支持按条码 / SN 查询，查询参数化。
- 支持分页浏览，避免一次性加载大量记录。
- 支持导出 CSV，UTF-8 编码，可直接用 Excel 打开。
- 界面跟随主程序的主题与中英文设置，并提供空状态提示。

## 13. 主题与语言

### 切换主题

点击应用栏主题按钮，在经典、浅色、深色之间切换。切换立即生效，选择会被记住，下次启动沿用；若主题文件缺失，自动回退到内置资源。

### 切换语言

点击应用栏语言按钮，在简体中文与 English 之间切换。切换立即生效，无需重启。默认语言跟随操作系统，无法识别时使用英文。语言清单见 `Src/TreeATE/i18n/languages.json`，翻译文件为 `zh.qm` 与 `en.qm`。

## 14. 布局与位置记忆

- 菜单工具栏、条码工具栏与各浮动窗口的位置和显隐状态会在退出时保存。
- 保存位置为程序目录下 `Config\layout.ini`，下次启动自动恢复。
- 首次启动且无布局记录时，计数浮动窗口默认停靠在主窗口右下角。
- “视图”菜单中的工具栏列表显示可读名称：**菜单工具栏**与**条码工具栏**，可分别勾选显示或隐藏。
- 如需恢复默认布局，可退出 TreeATE 后删除 `Config\layout.ini`，再次启动即可。

> 布局记忆按程序目录保存。若安装目录无写入权限，请以具备权限的账号运行，或调整安装目录权限。

## 16. 错误提示与处理

| 提示形式 | 触发场景 | 处理建议 |
| --- | --- | --- |
| 顶部错误横幅 | 加载失败、条码不匹配、测试异常等。 | 阅读横幅文字；若带操作按钮，按提示执行；横幅会在设定时间后自动隐藏。 |
| 条码输入框行内提示 | 条码为空或不符合工程条码规则。 | 重新扫描或输入正确条码；核对系统选项中的条码规则。 |
| 按钮抖动反馈 | 条件不满足时点击测试等操作。 | 检查是否已加载工程、是否勾选测试项、是否输入条码。 |
| 状态位 ERROR | 测试过程抛出异常。 | 查看日志与测试树中的异常信息，必要时停止测试并排查设备或脚本。 |

## 17. 常见问题

**Q1：启动后无法加载测试工程？**

确认已登录成功、工作路径配置正确，且选择的文件为 `*.tpx`。若使用扫码加载，请核对条码规则与工程相对路径。

**Q2：点击“测试”没有反应？**

开始测试需要同时满足：已加载工程、至少勾选一个测试项、已输入条码。条件不满足时界面会给出行内提示或按钮抖动反馈。

**Q3：点击“停止”后测试没有立刻停下？**

这是预期行为。停止在测试项之间生效，当前测试项会执行完毕后再停止，以保护设备与测试过程安全。

**Q4：状态位显示“完成”而不是“良品次数”了吗？**

v3.1.0 已修正该问题。测试通过后状态位显示“完成 / Done”，良品次数只出现在计数卡片标题中。

**Q5：界面语言或主题切换后没有生效？**

v3.1.0 支持运行时立即生效。若未生效，确认 `i18n` 下的 `zh.qm` / `en.qm` 与 `Themes` 下的 qss 文件存在；文件缺失时会回退到内置资源。

**Q6：重启后窗口布局变了或计数窗口位置不对？**

布局保存在程序目录 `Config\layout.ini`。请确认程序目录可写；如需恢复默认，退出后删除该文件再启动。

**Q7：本地结果查询打不开或没有数据？**

确认本地结果库文件存在且当前账号有读取权限。TreeResults 以只读方式打开结果库；无网络时测试结果会本地留存，联网后可再上传。

**Q8：安装包应该以什么权限运行？**

请以管理员身份运行安装包，确保写入 `Program Files` 与公共快捷方式成功。

## 18. 状态回归人工验证清单

用于验证 Loading / Ready / GO / Pass / Fail / Error 六个测试状态在界面上的表现。建议在测试机上按下列步骤逐项确认并记录。

| 序号 | 状态 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| 1 | Loading（加载中） | 登录后点击“加载”，选择较大的 `*.tpx` 工程并确认。 | 条码工具栏状态位显示“加载中 / Loading...”，加载完成后自动切换。 |
| 2 | Ready（就绪） | 工程加载完成，不输入条码。 | 状态位显示“就绪 / Ready”，工作区出现工程页签与测试树。 |
| 3 | GO（测试中） | 勾选测试项，输入条码，点击“测试”或按 F5。 | 状态位显示“测试中 / GO...”，KPI 与测试树实时更新。 |
| 4 | Pass（通过） | 使用 `Example\TestDemo` 等通过用例完成一轮测试。 | 状态位显示“完成 / Done”，计数区良品次数加 1。 |
| 5 | Fail（失败） | 使用包含失败测试项的工程，或将测试标准改为必然不通过，执行测试。 | 状态位显示“失败 / Failed”，计数区不良次数加 1。 |
| 6 | Error（异常） | 使用会抛出异常的测试脚本，或断开设备后执行依赖该设备的测试项。 | 状态位显示“ERROR”，日志出现异常信息，顶部可出现错误横幅。 |

### 公共检查项

- 每个状态的颜色与文字同时变化，颜色区分明显。
- 切换英文界面后，状态位分别显示 Loading...、Ready、GO...、Done、Failed、ERROR。
- 状态位宽度固定，不因文案变化导致工具栏抖动。
- 状态切换过程中，“加载 / 测试 / 停止”按钮的可用性符合当前阶段。
- 测试完成后再次扫描条码可进入下一轮，状态位可从“完成”回到“就绪”或“测试中”。

> 记录建议：状态、操作时间、条码、测试工程、实际显示文字与颜色、是否与预期一致；异常时附日志截图。
